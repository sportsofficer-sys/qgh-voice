# QGH Voice v4.4.0 - Radio & Orbit

Web/PWA release approved by the user after local preview, 5 September 2026.
Public address: https://sportsofficer-sys.github.io/qgh-voice/.

## What changes

- Single-aircraft callsign input, with an optional spoken callsign in single-aircraft exercises. Tactical voice commands remain aircraft-specific.
- Aircraft D/F stays live during its simulated transmission, holds the last indication for two seconds after release, then clears. Ground indication remains off.
- Deterministic pilot replies and informational RT acknowledgements, with red feedback and existing control highlights. Unsupported actions are identified as not simulated.
- Pilot speech is muted by default. HEADPHONES / PILOT READBACKS enables an installed local English voice. Controller PTT, recognised speech in continuous headphone mode, and supported new manual manoeuvre commands can interrupt an obsolete reply. Manual flight controls do not depend on voice recognition.
- Headphone replies target approximately 100 words per minute using a relative speech rate of 100/150. This is an estimate, not a calibrated WPM guarantee; installed voices vary. The audio watchdog allows 15 seconds. Aircraft motion, the exercise clock and muted transmission timing are unchanged by speech pace.
- Normal QGH heading-passing reports are aircraft-specific, one-shot and report at the crossing. Busy-channel reports wait and identify a delayed crossing as PASSED. U/S Compass does not disclose heading reports.
- Continuous left/right orbits retain finite-radius turns at selected speed/rate. CONTINUE ORBIT keeps circling. RESUME NORMAL finishes the current circle and resumes the pre-orbit heading. Separate heading commands override the orbit; U/S STOP TURN NOW rolls out on the current heading.
- Four tactical aircraft cards fit a compact two-column phone layout. The in-app user guide documents the controls and limitations.

## Validation

- 172 Node tests pass, including 10 Normal and 10 U/S random exercise handler runs, heading-crossing boundaries, orbit closure/rollout, formation behaviour, radio interruption, offline recognition routing, muted fallback, local-only synthesis selection and the slower-speech watchdog.
- Seven review perspectives were completed, followed by independent validation of three radio defects. Fixed silent continuous-listening resume retaining the radio channel, terminal microphone errors blocking manual replies, and manual speed changes leaving obsolete readbacks queued. Regression tests cover each, plus actual synthesis cancellation and recognizer partial-event forwarding. Interrupted replies are discarded rather than resumed; a new accepted command receives a fresh reply. Physical-device timing still requires user testing.
- Prior local browser verification covered the single exercise controls and a four-aircraft phone layout. The user confirmed real headset voice operation and approved publication. Automated tests use simulated transcripts/audio events; they do not establish recognition accuracy or training efficacy.
- Exact speech pace, audio availability and physical-device offline behaviour still depend on the browser/device. No claim of certified ATC training or operational suitability is made.

## Release boundary and update

Only the web app is built and published. Windows/Android source version metadata is aligned to 4.4.0 / code 20 for the existing release guard, but no native asset sync, installer/APK build, signing or distribution is performed. Existing native binaries remain unchanged.

The new version changes the service-worker cache and asset URLs. Existing users should finish or terminate their exercise, then choose UPDATE when offered. The cached offline voice model is retained separately. No private signing material, temporary preview files or unrelated design-qa.md edits are included.

## Post-Deploy Monitoring & Validation

During this release, the publishing agent verifies the GitHub Pages deployment result, live app-version.json, both exercise pages and hashes of the changed runtime assets against the validated build. Healthy signals: version 4.4.0, matching asset hashes, complete application shell and passing workflow tests. If the deployment fails or assets differ, do not announce success; inspect the failed job and correct or revert the release through a new reviewed commit. No background telemetry, microphone recording or ongoing monitoring is added.
