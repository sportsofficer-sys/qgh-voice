# v4.4.1 — Headphone Pilots

Web release for [Reds QGH Simulator](https://reds-aviation.github.io/qgh-voice/).

## What changes

- Pilot speech starts muted on every visit. Enabling it requires the headphone warning, a completed sample playback, and the user's confirmation that the sample was heard through headphones.
- Muting remains available. Reported audio-device changes and leaving the page invalidate confirmation. This is user confirmation, not guaranteed headphone detection.
- Four packaged male voices replace operating-system pilot voices in the web app. Single/A uses Michael, B Fenrir, C Puck, and D George. Each tactical voice stays with its aircraft when selection changes.
- The voice bank is included in the initial offline download: 14,296,537 bytes across nine verified assets. Pack readiness is shown on the entry page, with retry after interruption or storage failure. Only Michael is decoded for the first headphone test; other banks are decoded on first use to reduce initial memory.
- Accepted replies are assembled locally from audio clips. The application does not run a neural speech model or use a cloud speech service for pilot replies. Unlisted custom callsigns are spelled as individual letters; numbers are spoken digit by digit.
- Pilot replies target approximately 100 words per minute on every device. Build-time tempo normalization preserves pitch; composed test replies measure 96.62 WPM including pauses.
- Controller priority, immediate command execution, red readbacks, button highlighting, manual controls, and simulated D/F remain available. No changes are intended to flight physics, exercise controls, or the Normal/U/S distinction.

## First use and updates

Use the new link above. The former `sportsofficer-sys.github.io` Pages address does not redirect after the account rename. An installed PWA from the old address should be replaced with an installation from the new address.

Stay online until the entry page confirms that pilot voices are saved. Controller speech recognition still has its separate one-time **SET UP OFFLINE VOICE** download. Test both functions in airplane mode on the actual training device before use. Reloading clears the exercise; complete or terminate it before choosing an update.

For spoken pilot replies, open **VOICE**, select **PILOT REPLIES**, wear headphones, complete the test, and confirm. Mute before removing or disconnecting headphones. Some device-route changes are not reported by browsers. Manual input and visual acknowledgements do not depend on audio.

## Verification

- 225 automated tests pass, covering simulation/voice routing, Normal/U/S restrictions, consent lifecycle, clip assembly, lazy loading and retries, cache integrity, and release/build checks.
- 12 browser UI flows pass across Single/Tactical, Normal/U/S, and 1366-, 360-, and 412-pixel viewports. These UI tests stub audio; real audio is checked separately.
- Real offline service-worker, worker, and Web Audio testing confirms all nine cached assets, a fresh offline load, completed headphone test, immediate replacement turns, manual advance after muting, and a muted reload. No external requests or page errors were observed.
- All four voices completed real offline playback after the loader change. The nine-word sample lasted 5.58 seconds for each voice (96.77 WPM); observed playback-start latency was 4.5–43.9 ms on the test PC. These are PC measurements, not phone performance claims.
- A real previous-release worker with its saved audio opt-in remains active while new Single and Tactical pages load. Both now enforce fresh consent before the waiting update is activated.
- Maximum-length custom callsign audio remains live past the former 15-second watchdog and releases D/F on actual completion. Missing or invalid duration metadata retains a bounded recovery timeout.
- Eight review perspectives completed. An independent validation batch confirmed three changes to apply: upgrade coherence, duration-aware playback, and on-demand voice-bank decoding. All three are implemented and verified. No external independent-provider review is claimed.

The original four normalized voice-bank samples measured 96.62 WPM including segment pauses. The loader change does not alter those samples. Generation/cancellation and manifest checks are automated; no trained model is required on a phone.

Physical phone microphone accuracy, audible headphone routing, and device-change reporting require device testing. Browser viewport testing is not physical phone testing. This release does not claim a guarantee against speaker-to-microphone feedback when the user confirms an incorrect output route.

## Packaging and rollback

This is a web-only release. No Windows installer, Android APK, or Android App Bundle is built or published by this change. Source version metadata is reserved together to satisfy the existing alignment checks; previously distributed native packages do not update automatically.

The static web build includes only allowlisted runtime files and the manifest's verified voice assets. Render tools and raw model inputs are not deployed. Third-party notices accompany the voice bank; the application remains MIT licensed.

To roll back the web behavior, redeploy the prior known-good web source with a new monotonically increasing release version. Do not reuse a service-worker cache version with different contents. A rollback to the older audio implementation also loses the new headphone-confirmation protections.
